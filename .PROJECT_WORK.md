## 1. Purpose and context

The group project is designed to help you apply the end-to-end text analytics workflow in a
realistic, business- or social science-oriented use case: from data collection and preprocessing
to modelling, evaluation, visualization, and responsible communication of results.

## 2. Project scope

Each group (3–4 students) selects one text analytics problem and **delivers three milestone
documents plus a final presentation**. The project work and the presentation are mandatory
for every student. Projects must be feasible within the semester and demonstrate an end-to-end
workflow, including reproducible code and validated outputs.

### 2.1. Topic selection guidelines

- Your question should be a meaningful puzzle, i.e., a research question that identifies a
    gap, contradiction, or unexplained phenomenon in existing literature that demands a
    solution and clearly connected to text mining applications. The puzzle may also arise
    from revisiting an established research question with new computational tools, novel
    textual data sources, or innovative measurement strategies that allow for insights that
    were previously unattainable.
- The project must be feasible within the timeframe and data access constraints.
- The corpus and the research question should fit each other.
- Aim for added value (new corpus, new insight, or a well-documented
    reproduction/extension).

### 2.2. Recommended content structure

**1. Milestone 1: Research plan**
    - Motivation and context: Explain the real-world relevance and why the problem matters
       for business and/or society. You may support your motivation with either a brief
       literature-based background or other credible evidence (e.g., industry reports, statistics,
       policy documents, official analytics reports, reputable media/market research).
    - Problem statement and research questions/hypotheses: formulate clear research
       questions or testable hypotheses.
    - Data sources and corpus design: where the texts come from; unit of analysis
       (documents); language(s); expected corpus size; available metadata fields; basic data
       quality expectations.
    - Planned methods (can be modified later if needed): preprocessing, representation,
       modelling (classification/topic modelling/clustering, sentiment, NER, etc.).
    - Project plan: tasks and responsibilities by team member, timeline.

**Deliverable for Milestone 1: Submit one Research Plan document that includes all
sections above:**

- Length: 1-3 pages (excluding title page and references)
- Format: PDF file
- Title page including the project title, course, group name, team members, date


- Style: Times New Roman, 12 pt, single (1.0) spacing
- Structure: clear headings, concise bullets where helpful
- References: include a short **References** section (any consistent citation style is fine)
**2. Milestone 2: Progress report & analysis-ready corpus**
- Updated plan, extended with:
- Detailed corpus overview: encompassing the final/updated description of the data
sources, scope, and sampling decisions. Clearly justify why this corpus is
appropriate for the research question.
- Preprocessing pipeline: provide a structured description of the preprocessing steps
and their rationale. Include: cleaning decisions, feature construction choices,
before/after examples of text.
- Exploratory text analysis: conduct and document initial descriptive analyses, such
as word/term frequencies, n-grams, key terms (TF-IDF), KWIC, readability/lexical
diversity, initial visualizations, etc.
- Key corpus statistics: Include a summary table reporting core characteristics of the
dataset such as the number of documents, average/median document length,
language distribution (if multilingual), time span (if applicable), key metadata
coverage (missingness rates per field), duplicates/removed records (if relevant),
etc.), any additional corpus-specific indicators.

or analytical strategy and a brief interpretation of preliminary findings.
- Reflect on challenges encountered (data quality, ambiguity, class imbalance, etc.)
and how you address them.
- Tasks and responsibilities by team member.
- Cleaned corpus, schema and documentation: A readily usable data frame/CSV file
prepared for analysis.
- Challenges encountered (data quality, ambiguity, class imbalance, etc.) and how you
address them.

## 4. Technical and reproducibility requirements

**Reproducibility is mandatory.** The instructors will only evaluate and grade projects that can
be reproduced from the submitted package. If the workflow cannot be executed to regenerate
the main results (tables/figures/metrics), the project is not eligible for marking.

- Provide a reproducible workflow (e.g., Python notebook).
- Your code should create (at minimum) a corpus object, a document-level table/data
    frame/matrix; also include basic validation steps (e.g., previews, summary statistics,
    missingness checks, etc.).
- Visualizations must go beyond a basic word cloud (e.g., topic proportions, coefficient plots,
    embeddings projections, confusion matrix, time trends, similarity networks, etc.).
